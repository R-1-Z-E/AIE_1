# Итоговый проект по курсу «Инженерия Искусственного Интеллекта»

## 1. Паспорт проекта

- **Название проекта:** `Микросервис прогнозирования движения цены финансового актива`
- **Автор:** `Чечин Антон Сергеевич`
- **Группа:** `БББО-12-24`
- **Контакт:** `@Rize_1`

- **Краткое описание (2-4 предложения):** `Проект посвящён построению аналитического REST API сервиса для предсказания направления движения цены финансового актива на следующий день. По историческим котировкам (OHLCV) динамически генерируются технические индикаторы (SMA, Volatility, Momentum), на которых обучается модель Random Forest Classifier. Проводится обоснованный выбор гиперпараметров и генерация признаков. Результат — микросервис на FastAPI, который принимает технические метрики и возвращает торговый сигнал (BUY/WAIT) вместе с вероятностью роста.`

---

## 2. Структура проекта

Проект организован в следующей микросервисной структуре:

- `requirements.txt` – зависимости проекта.
- `Dockerfile` – инструкции для контейнеризации сервиса.
- `docker-compose.yml` – конфигурация для запуска в Docker.
- `Makefile` – алиасы для команд (make test / train / run).
- `pytest.ini` – конфигурация автотестов.
- `example_request.json` – пример валидного JSON-запроса к `/predict`.
- `report.md` – аналитический отчёт по проекту.
- `self-checklist.md` – чеклист самопроверки.
- `notebooks/` – исследовательские ноутбуки (EDA, проверка гипотез).
- `src/` – основной production-код:
  - `data/` – логика работы с датасетами;
  - `features/` – препроцессинг (расчет индикаторов);
  - `models/` – оркестрация обучения и сериализация;
  - `service/` – REST API приложение (FastAPI + Pydantic);
  - `utils/` – инфраструктурные модули (логирование и утилиты);
- `data/` – демонстрационная выборка котировок.
- `configs/` – конфигурационные файлы (YAML) и шаблон `.env.example`.
- `tests/` – модульные тесты (pytest).
- `artifacts/` – сериализованная модель (`.pkl`) и визуализации (`figures/`).

## 4. Как запустить проект

### 4.1. Запуск обучения модели

```bash
cd project
python -m src.models.train
```

Скрипт загружает сырые данные, вычисляет индикаторы, обучает модель и сохраняет артефакт в `artifacts/model.pkl`.

### 4.2. Запуск сервиса (REST API) локально

```bash
cd project
python -m src.service
```

Сервис поднимается на порту **8000** с использованием Uvicorn.

**Эндпоинты:**

| Метод и путь | Назначение |
|---|---|
| `GET /docs` | интерактивная документация Swagger UI |
| `GET /health` | проверка статуса сервера и загрузки весов модели в память |
| `POST /predict` | генерация торгового сигнала на основе переданных индикаторов |

**Проверка работоспособности:**

```bash
# health-check
curl http://localhost:8000/health

# запрос предсказания
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
    "sma_7": 45000.5,
    "sma_30": 44000.2,
    "volatility": 0.02,
    "momentum_3d": 0.015
  }'
```

Пример ответа `/predict`:

```json
{
  "action": "BUY",
  "probability": 0.76
}
```

### 4.3. Запуск через Docker

Упаковка и запуск сервиса в изолированном контейнере:

```bash
cd project
docker-compose up --build
```

## 5. Данные

- **Источник:** Открытое API Binance (эндпоинт klines), торговая пара BTC-USDT. Данные полностью деперсонализированы.
- **Хранение:** в репозитории (`data/trading_data.csv`) находится небольшая демонстрационная выборка (sample) для обеспечения воспроизводимости тестов и удобства проверки.
- **Особенности:** целевая переменная (направление цены) и признаки (индикаторы) не хранятся в файле, а генерируются динамически модулем `src.features.preprocess`.

## 6. Тесты

```bash
cd project
pytest tests/
```

Проект покрыт модульными тестами. Проверяется: консистентность датафреймов, отсутствие NaN после препроцессинга, логика генерации бинарного таргета, доступность ML-пайплайна и корректность HTTP-ответов от API, включая валидацию Pydantic-схем.

## 8. Ограничения и дальнейшая работа

**Текущие ограничения:**

- Модель предсказывает только бинарное направление (рост/падение), без оценки абсолютной величины изменения цены (регрессии).
- Отсутствует база данных для постоянного хранения истории запросов пользователей.
- Отсутствует логирование дрейфа данных (Data Drift).

**Направления развития:**

- Развертывание MLflow Tracking Server для полноценного версионирования экспериментов (вместо локального сохранения графиков).
- Добавление бустинговых моделей (XGBoost, CatBoost) в реестр для ансамблирования.
- Внедрение базы данных PostgreSQL для хранения истории предсказаний и метрик наблюдаемости.
